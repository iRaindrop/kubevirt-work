# KubeVirt beginner friendly issue backlog: recommendations

The following recommendations address the beginner friendly issue backlog of the KubeVirt user guide.

- Reopen the eight feature-lifecycle documentation issues (#918 through #925) that the stale bot closed in February 2026, confirm each is still valid against the v1.9 documentation, apply `lifecycle/frozen` and `help wanted` alongside `good-first-issue`, and link them from the Contributing page as the current starter set.
- Adopt a triage rule that every issue receives a `kind/*` label, a `sig/*` label (using `sig/documentation` for guide-wide items), and either `triage/accepted` or `triage/needs-information` within two weeks of filing. With twelve issues a year this is a small recurring task; assign it to a named maintainer or rotate it through the approvers listed in `OWNERS_ALIASES`.
- Exempt beginner issues from auto-closing: apply `lifecycle/frozen` to any issue labeled `good-first-issue` or `help wanted` at triage time, or ask the project-infra maintainers to configure the Prow lifecycle plugin to skip those labels in this repository.
- Seed and maintain a standing backlog of at least five to ten open `good-first-issue` items. Good sources are the findings from this analysis (for example, converting `$`-prefixed code blocks to fenced blocks page by page, replacing the 14 legacy `/api-reference/master/` links, removing minimizing language from specific pages, adding the missing Plugins page to `.nav.yml`, and deleting the duplicate Windows virtio drivers page), each filed as a single-page task using the #918 issue structure.
- Add a `kind/documentation` label to kubevirt/kubevirt beginner issues that require only a user-guide change, or file them in kubevirt/user-guide instead, so the two repositories the Contributing page names both offer documentation starter tasks.
- Record a triage decision on the two unlabeled open issues: state whether the Simplified Chinese documentation proposal (#950) is accepted and under what process, and label the Material theme end-of-life report (#1014) with `kind/cleanup` and an owner.
- Consolidate the duplicate `good-first-issue` and `good first issue` labels into one, and update the Contributing page to link directly to the filtered issue list (for example `https://github.com/kubevirt/user-guide/issues?q=is:open+label:good-first-issue`) so newcomers land on the current set.
- Add a short "Claiming an issue" note to CONTRIBUTING.md explaining how to comment to claim, how `lifecycle/active` is applied, and what to do if a claimed issue stalls, so beginner issues move from open to assigned to closed by a pull request.
